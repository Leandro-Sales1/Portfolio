# CLAUDE.md

Este arquivo fornece orientações ao Claude Code (claude.ai/code) ao trabalhar com o código neste repositório.

## Comandos

```bash
npm run dev      # vite — servidor de desenvolvimento
npm run build    # vite build — saída em dist/
npm run lint     # eslint . --ext js,jsx --report-unused-disable-directives --max-warnings 0
npm run preview  # vite preview — serve o build de produção
```

- Gerenciador: **npm** (só existe `package-lock.json`). Node **22.x** via `engines` no `package.json`, sem `.nvmrc`.
- **Não existem scripts `test`, `format` ou `deploy`, nem runner ou arquivos de teste.** Não invente um comando de teste.
- O `lint` usa `--max-warnings 0`: qualquer warning quebra o comando, inclusive a regra `warn` de `react-refresh/only-export-components`.
- O `lint` fixa `--ext js,jsx`, então ignora silenciosamente outras extensões se um `.ts`/`.tsx` for adicionado depois.
- O `.eslintrc.cjs` usa `env: { browser: true, es2020: true, node: true }`. O `node: true` é necessário para os arquivos de config da raiz (`postcss.config.js` usa `process`); sem ele o `lint` falha inteiro com `'process' is not defined`. O `ignorePatterns` inclui `flowforge-saas-1` — ver a nota sobre o template no fim.
- Não há `.github/workflows/` nem `vercel.json` no repositório. O deploy é a integração git da Vercel configurada no painel (build `npm run build`, saída `dist`), fora do repositório.

## Arquitetura

**Entrada e composição.** `index.html` → `src/main.jsx` (`React.StrictMode`) → `src/App.jsx`. O `App.jsx` é a página única e o **único** dono do estado de idioma: guarda `isEn` e repassa o objeto de locale inteiro por props. Não há router (`react-router` não é dependência), não há context, não há store.

`App.jsx` compõe, em coluna vertical: `Hero` → `About` → `TechsGrid` → `Projects` → `Contact` → `Footer`, todos em `src/components/sections/`.

- `src/components/ui/` — 5 primitivas: `Container`, `Section`, `Button`, `Badge`, `LangToggle`. **Pare aqui.** Não crie `Card`, `Heading`, `Text` ou `Stack`; os cards são estilizados inline com o padrão de borda de fio (ver `DESIGN.md`).
- `src/data/` — `techs.js` (os **20** ícones `{name, Icon, color}`, alinhados ao CV em 2026-09-23; o grid fecha 4 linhas exatas de 5 em `lg`), `socials.js` (LinkedIn/GitHub/WhatsApp) e `nav.js` (âncoras das seções). São a fonte única: a nav do Hero e a do Footer leem de `NAV`, então não têm como divergir.
- `src/utils/pointerGlow.js` — **não é hook e não observa nada**: são dois handlers (`setPointerGlow` / `clearPointerGlow`) que escrevem `--mx`/`--my`/`--rx`/`--ry`/`--lift` direto no DOM. Escrito assim de propósito, para não re-renderizar o React a cada `pointermove`.
- `src/utils/freeSpot.js` — duas buscas puras (sem DOM, sem three, sem React), que são as duas perguntas do posicionamento do fundo 3D do Hero: **`findFreeSpot(width, height, rects, {columns, rows, margin})`** devolve o **maior círculo livre** que não cruza nenhum retângulo (é o plano B e a régua de tamanho), e **`findSpotNearest(width, height, rects, {margin, minRadius, sizeFloor})`** devolve o ponto **mais perto do centro da tela** que ainda tenha `sizeFloor` (fração) do maior raio e `minRadius` (absoluto, em px) de piso — devolve `null` se nem o maior círculo alcança o piso, e aí quem chama fica com o maior vão. A régua do piso é medida **dentro** do `findSpotNearest`, com a mesma `margin` da busca: um piso absoluto vindo de fora comparava dois números medidos com réguas diferentes e nunca era alcançável. As duas são puras de propósito, para poderem ser exercitadas em Node com retângulos sintéticos.
- `src/utils/screenBudget.js` — a "função que lê o tamanho da tela" do fundo 3D, também pura: `viewportBudget(width, height, {hasPointer, devicePixelRatio})` devolve o que a tela dá (folga, teto, piso, `pixelRatio`, recuo em `z`, `centerSizeFloor`) e `envelopeWorldRadius({usedPx, fPx, distance, offsetPx})` inverte a silhueta. Recebe dimensões **já medidas** e nenhum retorno pode virar `className` (é o teste que impede a função de virar um `isMobile` de volta). **Não devolve nome de faixa** (`'phone'`, `'desktop'`) — enum é convite a `if (tier === …)`.
- `src/api/instance.js` — inalterado.

**O idioma é feito à mão — não existe biblioteca de i18n.** `src/locales/pt.json` e `src/locales/en.json` (29 chaves cada) são importados direto no `App.jsx`, e `const text = isEn ? en : pt` desce para todo componente como a prop `text`. Os componentes consomem o **objeto inteiro** (`{text.aboutMe}`, `{text.linkCV}`), não uma função `t()`. O switch é o `src/components/ui/LangToggle.jsx` (dois `<button aria-pressed>`), **não** mais um checkbox estilizado por CSS.

- **Português é o padrão**, mas a escolha **é persistida** em `localStorage` (`portfolio:lang`) desde o redesign; o `useState` inicial lê essa chave, então um reload mantém o idioma.
- Um `useEffect` no `App.jsx` sincroniza `document.documentElement.lang` (`en` / `pt-BR`) com o estado.
- **Toda string nova precisa existir em `pt.json` e `en.json`.** Chave presente em só um arquivo renderiza `undefined` — e **React renderiza `undefined` como nada, sem erro no console**. O modo de falha é uma seção silenciosamente em branco. Ao adicionar chave, compare os dois arquivos (`Object.keys` de cada um).
- Manter texto novo nos arquivos de locale, não nos componentes. Exceções deliberadas: nomes próprios (Leandro Sales, LinkedIn, GitHub, WhatsApp, nomes das techs), os **índices mono das seções** (`01`–`04`, neutros de idioma) e os **labels do painel de calibração** (ver abaixo).
- **As meta tags do `index.html` não acompanham o toggle de idioma.** `<title>`, `description`, `og:*` e `twitter:*` estão fixas em PT (o `<html>` é `lang="pt-br"` e o PT é o padrão); o `App.jsx` só sincroniza `document.documentElement.lang`. Trocar o texto dessas tags é editar o `index.html` à mão nos dois lugares (title+og+twitter), não o locale.

**O texto dos projetos é uma segunda camada de localização, e vem da API.** Cada objeto traz `descricao` (PT) e `descricaoEn` (EN), e o `Projects.jsx` resolve antes de descer a prop (`isEn ? card.descricaoEn || card.descricao : card.descricao`) — o `||` evita card em branco quando a versão EN não foi preenchida.

**Os cards de projeto vêm de uma API remota, não do repositório.** `src/api/instance.js` exporta um axios com `baseURL` **hardcoded** (`https://json-server-portfolio.vercel.app`, sem env var e sem fallback). Único consumidor: `Projects.jsx`, com `instance.get('/cards', { signal })` dentro de um `useEffect` com `AbortController`. Campos consumidos: `imagem`, `titulo`, `descricao`, `descricaoEn`, `link`, `gitHub`.

- **A API não tem campo `id`** (verificado em 2026-09-22: 7 cards, chaves `imagem, titulo, descricao, link, descricaoEn`, e `gitHub` presente em só **3 dos 7**). Então `key={card.titulo}` é a única opção — **quebra se dois projetos tiverem o mesmo título**.
- A falha da API virou três estados (`loading` / `ok` / `error`) com skeleton, mensagem traduzida e botão de retry. O antigo `alert()` bloqueante e fixo em português foi removido — não o reintroduza.

> Para mudar o conteúdo dos projetos, edite o JSON server externo — **não este repositório**. E os valores de `imagem` são caminhos absolutos `/imagens/...` resolvidos contra `public/`.

**Fundo 3D.** `src/components/backGround/ThreeCanvas.jsx` — `three` puro (`ShaderMaterial` com shaders GLSL de ruído simplex, `IcosahedronGeometry`, `AdditiveBlending` + 3 órbitas `EllipseCurve`). Não usa `@react-three/fiber`.

O contrato com o painel de calibração é **5 props que viram uniforms**: `distortion` → `uDistortion`, `detail` → `uSize` (`detail * 2.0`), `speed` → `speedRef` (lido dentro do RAF), `opacity` → `uOpacity`, `color` → `uColor`. Todas mudam **ao vivo após o mount**.

- O `useEffect` de init tem **deps vazias de propósito** e fecha sobre as props (daí o `eslint-disable react-hooks/exhaustive-deps` no topo). **Não adicione as props às deps** — o canvas seria destruído e recriado a cada arrasto de slider.
- O estado do painel vive no `Hero` como **um objeto** `params`; `HeroCalibration` é controlado (`params` / `onChange`).
- **`adjustLayout` NÃO usa mais números por breakpoint.** Duas tentativas anteriores usaram constantes (`y = -2.9` + escala `0.72` abaixo de 1024px, `x = 4.5` / `6.5` acima) e falharam nas duas: a esfera ficava atrás do painel no desktop e atrás do texto no celular. A conta é incompatível — a altura do texto é medida em PIXELS e a viewport em `svh`, então a sobra depende da largura **e** da altura e muda quando uma linha a mais quebra. Não existe constante que sirva de 320px a 2560px: **não reintroduza o posicionamento por faixa de largura.**
- **O posicionamento é medido, e a esfera vai o mais perto do CENTRO DA TELA que o tamanho permitir.** A ordem de prioridade é a do dono — sem sobreposição (restrição dura), depois tamanho, depois centro — e é ela que a implementação segue: `findFreeSpot` dá o maior vão (a régua), `findSpotNearest` dá o ponto mais perto do centro com ≥`centerSizeFloor` (0,9) desse raio, e o segundo vale quando existe. **As três exigências não cabem juntas em toda tela**: o meio da tela no desktop é um corredor entre o texto e o painel, medido em ∅198 contra ∅360 no vão — centrar ali custa ~metade do tamanho. Por isso a fração é 0,9 e não 0,6, e por isso existe um plano B.
- O Hero marca com `data-hero-occupied` o `div` do logo, a nav do desktop, a nav do mobile, as **5 folhas** do bloco de texto (eyebrow, `h1`, tagline, subline, CTAs) **e o wrapper do painel de calibração** — **folhas, não caixas**: `getBoundingClientRect` inclui o padding, e o `lg:pr-80` do bloco punha 320px de obstáculo além da tinta. **Cinco** dessas folhas (`h1`, tagline, subline, eyebrow, CTAs) levam `data-hero-occupied="ink"`: são `block`/`flex`, então a caixa vai até a borda da coluna — o `h1` mentia 200–280px para a direita e o eyebrow/CTA tinham 896px de caixa com ~300px de tinta, e a caixa mentirosa deles cai justamente na faixa do meio que o centrado procura. O `measure` usa `Range.getBoundingClientRect` **unido às caixas dos filhos** (o `Range` só pega nós de texto, e o eyebrow tem um ponto de acento que é `<div>`). O `ThreeCanvas` mede esses retângulos via `container.parentElement` — o div do canvas é *irmão* do wrapper, não ancestral. O grupo é escalado pela **silhueta**; abaixo de `floorRadiusPx` fica invisível. Detalhes e a tabela medida em `DESIGN.md`.
- **O painel de calibração É obstáculo**, e o wrapper dele leva `data-hero-occupied` (com o `hidden lg:block` nele, para medir 0×0 abaixo de `lg`). O vidro (`.tech-glass`, `z-30`) admitiria a esfera por trás, e houve uma tentativa de liberá-lo — mas atravessá-lo por baixo da moldura lê como defeito, e "sem sobreposição" é a restrição dura. O preço está medido: são ~317px de altura bloqueando a metade direita da faixa central, e é por isso que a esfera não fica no meio no desktop.
- **A escala é a inversão da SILHUETA, não a do polo próximo** — `envelopeWorldRadius` em `src/utils/screenBudget.js`. Medir a projeção no polo próximo (`d − ρ`) deixava a esfera desenhando **63% (desktop) a 72% (mobile)** do vão reservado; corrigido, as órbitas (desenhadas com raio exatamente `ρ`) enchem o círculo reservado por construção. Fora do eixo a projeção vira elipse alongada na direção radial e a tangência é resolvida por bisseção com o `offsetPx` — sem esse termo a esfera vaza o vão em tela larga. `ORBIT_RADIUS = 6.0` é **constante de propósito**: uma referência viva faria as órbitas encolherem 12% ao arrastar o slider de distorção de 0,6 para 2,0. A nuvem cresce com o slider e no extremo passa ~15% de `usedPx` do círculo — como esse excesso é **relativo** e o respiro é **absoluto**, eles só se igualariam por volta de `usedPx ≈ 210px`: hoje dá ~31px em 1024×768, ~43px em 1440×900 e ~69px em 2560×1440, ou seja **maior que os 32px de respiro em todo o desktop**. Quem absorve é a folga de **paralaxe** (~27px num hero de 900px, ~43px num de 1440px), e no valor padrão do slider (0,6) a nuvem fica em 79% do círculo, sem excesso nenhum. A troca segue consciente: quem manda no raio são as órbitas, e deixar a nuvem mandar encolheria as órbitas ~13% (detalhada em `DESIGN.md`).
- **O teto de tamanho é `0,42 * altura` e não entra.** Medido no DOM real, o maior círculo é ∅530 em 1904×984 — 27% da altura, contra os 84% de diâmetro que o teto permitiria. Ele é o freio contra número degenerado: sem ele `ρ` se aproxima da distância até a câmera e a tangente de `envelopeWorldRadius` explode com o `gl_PointSize` junto. (Houve uma versão com `0,32` enquanto a esfera estava no centro com o painel fora dos obstáculos; com o painel de volta ela não se sustenta.)
- **A folga é derivada, não constante.** `DEFAULT_MARGIN = 32` no `freeSpot.js` é só o padrão de quem chama a função solta; o Hero passa a sua, vinda de `viewportBudget`: **24px de respiro + 8px da animação de entrada** (`animate-fade-in` começa em `translateY(8px)` e a medição roda no mount) **+ a paralaxe da câmera em px** (`PARALLAX_WORLD * fPx / distance`, ~27px num hero de 900px, ~43px num de 1440px), esta última **só onde há ponteiro** (`hasPointer`; sem `mousemove` a câmera não anda). A folga de 8px de paralaxe que existia no papel era 3–5× menor que o real. A mesma folga **não** é usada contra as bordas do container, e a versão anterior deste arquivo registrava o contrário: existia um `edgeMargin` opt-in para isso, e ele saiu do módulo. Quando o maior círculo está encostado numa borda — e no desktop ele está, no topo — exigir 56px das quatro bordas tira **~15% do raio**, e a esfera centrada saía menor que o plano B. Ao **somar um elemento fixo ao Hero, marque-o** com `data-hero-occupied` — um elemento não marcado é um lugar onde a esfera pode cair em cima.
- A medição roda no mount, no `ResizeObserver` do container **e em `document.fonts.ready`** — Inter/JetBrains vêm do Google Fonts e chegam depois, e o texto medido com a fonte de fallback tem outra altura (o `ResizeObserver` não cobre isso: o container é `inset-0` e o hero é `min-h-screen`, então a caixa não muda quando o texto cresce dentro dela).
- **Não há mais desconto de opacidade no mobile.** O `opacity * 0.55` era paliativo para o enxame atrás do texto; com o vão livre não há sobreposição para o `AdditiveBlending` lavar, e o `uOpacity` é a prop direta.

**Estratégia responsiva.** Não existe detecção de viewport em JS: `src/utils/viewport.js`, `useViewportDimensions`, `isMobile` e o `<section>` com altura/largura inline foram **removidos**. O layout é coluna vertical. O `< 1024` do `ThreeCanvas` (que decidia o `pixelRatio` do renderer e o recuo em `z` — e **não** posicionava nada) **saiu de dentro do componente** para `viewportBudget`; onde a esfera fica continua medido, não estimado. Não recrie um hook de viewport — comportamento por breakpoint é classe `md:`/`lg:`.

**Estilo.** Tailwind 3 com tokens reais em `tailwind.config.js` → `theme.extend`: `fontFamily.sans` (Inter) / `mono` (JetBrains Mono), `colors.accent` (`#f97316`) / `surface` / `panel`, `transitionTimingFunction['out-expo']` (`cubic-bezier(0.16, 1, 0.3, 1)`, usada como `ease-out-expo`), e `keyframes`/`animation` de `fade-in` e `flow`. A identidade completa está em **`DESIGN.md`** — leia antes de estilizar qualquer coisa nova.

> **O variant `hover` (e o `group-hover`) foram sobrescritos no `tailwind.config.js`** para exigir ponteiro real: `@media (hover: hover) and (pointer: fine)`. Isso torna todo `hover:` do projeto touch-safe de uma vez, sem `md:hover:` espalhado. Os **dois** variants foram sobrescritos porque `group-hover` é um variant core separado — cobrir só o `hover` deixava as 4 regras de `group-hover` grudando no toque. Se um dia um hover precisar valer em telas de toque, ele **não** vai funcionar por esse caminho: use `active:` ou `focus-visible:`.
>
> O sistema de hover é fechado: **300ms** para superfície/card, **200ms** para botão/ícone, sempre `ease-out-expo`, e **todo** elemento interativo tem `focus-visible:ring-2 ring-accent/70`. Hover de movimento (`-translate-y-*`) e `.card-tilt` **não convivem** no mesmo elemento — os dois escrevem `transform` e o inline vence. Ver "Hover" no `DESIGN.md`.

> O CSS compilado do Tailwind 3 é **plano**: `@layer` aparece **0 vezes** na saída (é construct de compilação, não de runtime). A ordem efetiva é base → components → utilities não-prefixadas → regras custom → utilities responsivas. Logo, uma regra custom vence uma utility não-prefixada, mas **perde** para a responsiva. **Nunca conte com uma classe do `index.css` para sobrepor `md:text-6xl`.**
>
> Pela mesma razão, **`className="px-4"` não sobrepõe um `px-5` interno de um componente** (a cascata é a posição no CSS gerado, não a ordem no `className`). Por isso `Button` expõe `size` e `iconPosition` como props em vez de deixar o chamador passar classes conflitantes. Não há `clsx` nem `tailwind-merge` — decisão consciente; as primitivas concatenam `className`.

## Convenções e armadilhas conhecidas

- **Não há `prop-types`** em lugar nenhum, embora o ecossistema esteja carregado no ESLint. Todo componente com props abre com `/* eslint-disable react/prop-types */`. **Siga a convenção de disable por arquivo** — não introduza `prop-types` nem migre para TypeScript sem que isso seja pedido.
- O `.eslintrc.cjs` fixa `settings.react.version` em `'18.2'` enquanto o React **19** está instalado — defasado, e fonte de regras do `plugin:react/recommended` disparando de forma imprecisa. O `parserOptions` também não define `ecmaFeatures.jsx`.
- **Os labels do painel de calibração são em inglês e hardcoded** ("System Calibration", "Flux Dynamics", "Processing Threads", "Clock Rate", "Density", "Energy Profile"). **É deliberado**: são readouts de instrumento, não prosa — em ferramenta real são idênticos nos dois idiomas. Não "conserte" isso para o locale sem falar com o dono do projeto.
- **Cor do ícone de tech vai na custom property `--brand`**, via `style={{ "--brand": color, "--glow": color }}` no tile, e o ícone usa `group-hover:text-[color:var(--brand)]`. O `--glow` é a mesma cor e alimenta o `.pointer-glow` (sem ele o spotlight do tile sairia no acento, não na cor da marca). Não volte para `style={{ color }}` direto no ícone: era esse o motivo de o `hover:text-black` do portfólio antigo nunca funcionar (a cor inline vencia a classe).
- **Marcas de cor branca** (`#ffffff` em Next.js e Express): o `group-hover:text-[color:var(--brand)]` não produz mudança visível nelas. O feedback vem do `scale-110` + `drop-shadow-[0_0_14px_currentColor]`. Não "conserte" trocando a cor oficial da marca.
- **Duas techs do grid não têm glifo de marca** em `react-icons@5.0.1`: **Claude** (usa `TbSparkles`, glifo genérico de IA, com a cor oficial `#D97757`) e **Codex** (usa `SiOpenai`, a marca dona — mesmo critério do Gemini, que aparecia com `SiGoogle`). Subir a lib **não resolve**: verificado no runtime em 2026-09-23, o 5.7.0 traz `SiClaude` mas remove `SiAmazonaws` (que fica no grid), `SiPlaywright` e `SiOpenai`, e continua sem glifo de Codex. Só troque o `Icon` se a lib ganhar o glifo sem perder os outros.
- Os labels de tech **são os nomes próprios das marcas** — não vão para o locale (é a mesma exceção dos nomes próprios), e a lista vem inteira de `techs.js`.
- **O Hero depende de empilhamento explícito** (`z-0` glow / `z-[1]` canvas / `z-[2]` `.grid-overlay` / `z-20` conteúdo / `z-30` painel) e de `relative overflow-hidden` no `<section>`. Nunca use z negativo. O grid fica **acima** do canvas — atrás dele a grade de 32px ficava invisível sob o `AdditiveBlending`. Detalhes em `DESIGN.md`.
- **O padding horizontal do Hero mora no wrapper, nunca no `<section>`.** O wrapper repete a coluna do `Container.jsx` (`mx-auto w-full max-w-7xl px-6 md:px-12`, em `max(…, env(safe-area-inset-*)` com `viewport-fit=cover` no `index.html`); o `<section>` fica só com padding vertical, para o canvas continuar full-bleed. Se o padding horizontal voltar para o `<section>`, o `max-w-7xl` já vem encolhido 48px e o Hero sai desalinhado de todas as outras seções.
- **`text-balance` é utility nativa** do Tailwind 3.4 — não recrie no CSS. E **`min-h-svh` não existe** na 3.4.19: a altura do Hero usa `.hero-vh` com `@supports` no `index.css`.
- O `three` é dependência **direta e usada** (`ThreeCanvas.jsx`). Removidas no redesign e **não reintroduzir sem motivo**: `@react-three/fiber` (só era usado pelo antigo `Bg3D.jsx`), `motion`, `clsx`, `tailwind-merge`. O bundle caiu de >1 MB (~318 kB gzip) para **~767 kB (~219 kB gzip)** — a alta de ~18 kB em 2026-09-23 são os ícones novos de techs.
- O bundle ainda passa de 500 kB e o Vite avisa no `build` — é o `three`. **O aviso é esperado, não é erro de configuração.** Em 2026-09-23 está em **~768 kB (~220 kB gzip)**.
- **O painel de calibração tem um wrapper posicional no `Hero`**, e o `hidden lg:block` mora nele, não no painel: abaixo de `lg` o wrapper precisa medir 0×0 (se o `hidden` ficasse no painel de dentro, o wrapper continuaria com a altura dele e a esfera desviaria de um obstáculo invisível). O wrapper **não** leva `data-hero-occupied` — o vidro admite a esfera por trás. O painel em si é `flex flex-col` (o `flex-col` sem `flex` era o bug do template: a partir de 1024px o painel virava `flex-direction: row` e o conteúdo transbordava a moldura de vidro).
- Comentários e identificadores são em inglês; o português em `src/` é a cópia do `pt.json` e as mensagens de locale.
- **`origin/dev` é um protótipo divergente e obsoleto**, não um branch de feature a ser mergeado: ele adiciona `src/assets/Cards.json`, `banner/`, `rodape/`, `cardProjetos/` e remove `Bg3D.jsx`, `Techs.jsx`, `utils/viewport.js` e a API axios (passando a usar JSON local). Se pedirem "merge da dev", **confirme a intenção antes**.

O `linkCV` no locale é só o nome do arquivo — **a barra inicial vem do componente**. Renomear ou substituir um CV significa atualizar `linkCV` nos dois arquivos de locale.

- As demais imagens de `public/imagens/` **não são referenciadas por código em `src/`**: quem as referencia é a API remota, que devolve caminhos como `/imagens/mind-guard.png` resolvidos contra este mesmo `public/`. Adicionar um projeto exige **as duas coisas**: soltar a imagem em `public/imagens/` **e** adicionar o objeto na API externa — mexer só neste repositório não faz o projeto aparecer.
- O favicon é `/imagens/favicon.ico` (absoluto, `type="image/x-icon"`) — era o único caminho relativo do projeto e estava rotulado `type="image"`.

> `flowforge-saas-1/` era o template de referência do redesign visual. Está no `.gitignore` e **deve ser apagado** ao final do port; nada em `src/` importa de lá. Se a pasta reaparecer, trate como referência descartável — não a commite e não importe nada dela.
